The problem

01Waybill's `next` reports; it does not drive. `commands/next.md:51-61` instructs the session to show the CLI's waybill block verbatim and stop — "It is already the whole answer" — and running the commands it lists is explicitly the next session's job. The only override is a `RUN:` line, which the CLI prints only when the operator has already pasted `/waybill:next <branch>/<leg>` after clearing. Every leg boundary on the eight-leg route is therefore a manual relay.

02That relay costs roughly 28 paste blocks per effort: each `handover: transfer` leg renders `/clear`, `/model`, `/effort` and the command; each `through` leg renders three. Eight legs, eight stops. Four of those stops — `bay`, `specs`, `execute`, `cleanup` — ask nothing of the operator's judgment; they are pure transport, and the operator is the conveyor belt.

03The sharpest cost is not keystrokes but presence. Because nothing advances without a paste, an effort cannot progress while the operator is away, even across `specs` and `execute` — the two longest legs on the route, and the two that most obviously want to run unattended. A route designed to be walked in sessions currently requires a human at every session boundary, including the boundaries that exist only for context hygiene.

Goals ×5
01 Under `--autopilot`, halt exactly once per gate the command can reach — three halts (`refine`, `contract`, `review`) rather than today's eight — and never halt for transport.
02 Walk a complete eight-leg route in at most 6 `/waybill:next` invocations, down from ~28 paste blocks; the fourth operator stop belongs to `/waybill:new` conducting `ideate` and is unchanged by this work.
03 Raise the longest unattended run from 0 legs to 2, so `specs` and `execute` cross without the operator present.
04 Make gate membership explicit data — a `gate` field on the route — rather than prose scattered across `commands/*.md`.
05 Preserve the context hygiene that `handover: transfer` buys: a leg whose booking names a more capable model than the running session must never run degraded in silence.

MVP — must ship ×11
  • A `gate` field on the route in `src/legs.js`, true for `ideate`, `refine`, `contract` and `review`— Everything else keys off it; gate membership must be data, not prose. `ideate`'s flag is documentation-only — `next` never reaches that leg.
  • `/waybill:next` executes the next leg — invoking its carrier in-session rather than printing paste blocks— The core verb change; the whole point
  • `/waybill:next` conducts a gate leg and then stops, crossing nothing after it— "Take me to the next human gate, then walk me through it" — the gate is conducted, not merely arrived at
  • `/waybill:status`'s in-bay answer gains the waybill paste blocks; the trunk fleet listing keeps none— The manual relay must stay reachable or a model mismatch has no escape hatch. The fleet listing never carried a waybill and must not start.
  • `/waybill:next --autopilot` crosses non-gate legs until a gate, conducts it, and stops— Where the unattended reach comes from — it crosses `specs` and `execute`
  • Stop-and-ask when a crossed leg runs but its stamp does not flip: one prompt offering retry, inspect, or stop— The only thing preventing a runaway loop; chosen over a silent halt so a failure becomes a decision
  • A non-gate leg booked `handover: transfer` is dispatched to a subagent at its booked model; `through` legs run in-session; gate legs are never dispatched— `transfer` already means "this leg wants its own fresh context", and a subagent is exactly that. This is how autopilot crosses `specs` and `execute` at all — without it MVP autopilot crosses nothing worth crossing.
  • A run log naming, per crossed leg, the model it actually ran at— The only way a dispatched leg and an in-session one are told apart after an unattended run
  • `cleanup` pre-flight: crossable when the bay is clean, halting with the ask on a dirty worktree, unpushed commits or an unmerged branch; gitignored papers deleted but named in the log— Pre-approving cleanup's destructive git steps is what lets one autopilot run finish an effort; the pre-flight is what keeps that from discarding real work unattended
  • Sweep every prose surface describing `next` as show-and-stop — repo-root README, docs/guide, commands/*.md, src/help.js — and add the missing root-README assertion to the suite— docs/ideation/learnings.md records this exact gap from next-from-anywhere, and no test today reads the repo-root README at all
  • Update `docs/guide/03-reference.md` in the same phase as each new booking key and CLI flag— tests/guide.test.js:202-206 asserts every booking key and every USAGE flag appears there, so deferring the doc reddens the suite in the phase that adds the key
Full — target outcome ×1
  • A `gate:` key in booking frontmatter overriding the route default in either direction— Lets a solo operator un-gate `review` on their own machine; per-machine preference, not load-bearing for the paste-count goals
Stretch — if time permits ×1
  • `--autopilot --dry-run`: print the run autopilot would make, and where it would stop, without running anything
Out of scope — said no on purpose
  • Effort fidelity on dispatched subagents — A subagent takes `model` but not `effort`; a dispatched `execute` runs opus-at-default rather than opus/high. Accepted and documented rather than worked around.
  • Splicing non-stock legs into the route via `after:` — Already deliberately deferred to Future in commit 0c5c5fc; overlays rebook and re-gate the eight stock legs, never add a ninth
  • Fleet-wide autopilot across several open dockets — One docket per invocation, as `next` works today
  • Any retry beyond the single ask — no backoff, no automatic second attempt, no repair logic — One attempt per leg keeps the failure mode legible
  • Changing `ideate`'s stamp or giving it a paper — `next` never reaches `ideate` (src/cli.js:278, src/legs.js:131), and a paper written before `bay` exists would land in the main checkout — the one thing waybill's design prevents
  • Gate awareness in `/waybill:new` — `new` already conducts `ideate` and stops; the scope named was next, status and autopilot
  • Discovering the running session's model, and any model-capability ranking table — Nothing in src/ can learn the session's model — only HOME, WAYBILL_BAY_DIR and WAYBILL_BOOKINGS_DIR are read anywhere — and a haiku<sonnet<opus table would go stale each model generation. `handover: transfer` is the trigger instead.
Future — someday, maybe
  • Detecting session cleanliness rather than assuming it, if assuming-clean proves wrong in practice
  • Making `effort` settable on a dispatched subagent, should the harness ever expose it
  • A gate that is situational rather than static — a leg becoming a gate because a stamp returned STAMP_UNKNOWN or a diff crossed a size threshold

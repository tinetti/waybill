A token on a finished docket, or on a leg with no booking

Context
The spec did not cover a leg token when state.leg is null or no booking is bound.
Decision
Print no keyed line: no RUN (nothing to run) and no NEXT LEG (no next leg to name). The waybill below already says which.
Alternative
Printing NEXT LEG: null, or a RUN with an empty command.

A cleanup token never enters the bay

Context
The spec suppressed ENTER BAY for a cleanup token but did not say whether that applies to a stale one.
Decision
Suppress it for any cleanup token, stale or matching (src/cli.js issueWaybill).
Alternative
Suppressing it only when RUN matches the cleanup leg.

bay-cut.md minted from the CLI, not a pure render

Context
The contract's MVP item said a pure render with a fixed path; the spec said the CLI output with the path normalised.
Decision
Use the CLI output, with the temp bay path replaced by /repo/.claude/worktrees/waybill-feat-thing, so the golden also pins bay's heading.
Alternative
A pure renderWaybillMarkdown call, which would duplicate refine.md.

USAGE keeps next [<branch>]

Context
Widening the USAGE row to next [<branch>[/<leg>]] needed two lines, and tests/help.test.js parses USAGE one row per subcommand.
Decision
Keep the one-line row. The leg form is documented in the README, the living spec, and next.md's argument-hint.
Alternative
Change the help parser to accept wrapped rows.

The problem

01Waybill's only fleet view today is `waybill status` run from a repository's trunk, which reaches `renderFleet()` at src/cli.js:328 and prints one line per docket in that single repository — `feat/work-laptop-readiness · leg 5 of 7 (specs)`. That is the entire picture. There is no age, no indication of which docket has stalled, no signal about which is closest to done, no record of which branches were cut from which, and no visibility whatsoever beyond the current repository.

02The operator runs 5–10 dockets at once, spread across several repositories under ~/Projects. Four concrete failures follow. Stalled dockets go unnoticed — a branch sits untouched for days and nothing surfaces it until it is stumbled back into. There is no signal for which docket to advance next, so selection is guesswork. Branches cut from other branches get merged out of order, producing conflicts or a broken trunk, because nothing anywhere records that B was stacked on A. And starting the day means running `status` in each repository in turn, checking git by hand, and reconstructing the whole picture mentally.

03None of this is blocked by missing data. Waybill is stateless by design (docs/guide/02-glossary.md:44 — 'reads the stamps off the repository every time and keeps no state file'), and `fleet()` at src/fleet.js:31 already enumerates every open docket with its branch, worktree path and resolved leg. Progress exists as leg index/7 for every docket and as done/total tasks for the execute leg (src/progress.js:149). Age and stacking are one git call each. The view simply has never been written.

Goals ×6
01 One command, run from any directory, lists every open docket in every git repository at or beneath the working directory to a configurable depth defaulting to 4 — missing no repository with an open docket, showing no repository without one, and counting a repository exactly once however many of its bays fall inside the scan.
02 Every docket row carries three facts absent from any waybill surface today: a progress bar, time since the branch opened, and time since it was last touched.
03 Each docket additionally shows its stacked-branch parent where one exists, and whether a tmux pane is open on its bay together with what is running there — with all three degrading to blank rather than to a false claim when tmux or ps is absent or unreadable.
04 In live mode the first frame paints before the slow lane — openspec task counts and the ps process walk — has resolved, targeting 500ms at 10 dockets across 3 repositories; the one-shot path instead waits for complete data, because a single frame printed early would omit task counts permanently rather than filling them in.
05 In a TTY the view self-updates every ~2s until dismissed with `q`, with `r` forcing an immediate repaint and slower data filling in after the first frame; piped or redirected it prints exactly one frame and exits 0, so `fleet | grep` and every golden-file test work unchanged.
06 Ships with zero new dependencies, no build step and exactly one package script, leaving the zero-dependency assertion at tests/commands.test.js:540-553 passing without modification.

MVP — must ship ×11
  • `waybill fleet` CLI verb wired into COMMANDS and USAGE (src/cli.js:588, :31), plus commands/fleet.md with its bang line, its entry in the DECLARED list at tests/commands.test.js:32-43, and its /waybill:fleet row in docs/guide/03-reference.md— The surface itself; and tests/guide.test.js:197 plus tests/commands.test.js:113 make the prose and list edits mechanically required, not optional polish
  • An OpenSpec change with a MODIFIED command-surface requirement admitting the fifth verb, stacked on the pending add-help-card delta's wording— openspec/specs/command-surface/spec.md:10-19 states the surface SHALL consist of exactly four verbs; shipping fleet makes the living spec false unless the delta lands with it
  • Single-repository mode — cwd inside a repo renders that repo's fleet— Builds on fleet() at src/fleet.js:31; the cheapest path to a working command
  • Multi-repository scan when cwd is not a repository, with `--depth` defaulting to 4, halting descent at each repository found, deduplicating by main checkout, and resolving bookings per discovered repo root— Running from ~/Projects is the stated primary use; dedup and per-repo bookings are load-bearing because the supported waybill.baydir=.. layout puts bays in the scan path and overlays are per-repository
  • Execute-leg progress made deferrable so the openspec CLI lookup is off the synchronous critical path— fleet() → resolveLeg() → executeProgress() shells out to openspec once per docket today (src/inference.js:117,156 → src/progress.js:149); without a slow lane the 500ms goal is unreachable
  • Repositories with no open dockets hidden, with a scanned-count footer— At depth 4 most repositories are clean; every visible line must be actionable
  • Progress bar — leg index/7 with the execute leg interpolated by task done/total when available— Answers 'which should I advance next?'; execute is where time is actually spent, so a frozen bar there would defeat the feature
  • Age columns: opened (merge-base date) and idle (tip committer date), with `now` injected into the renderer— The neglect alarm for 'stalled dockets go unnoticed'; injection preserves byte-stable goldens
  • Grouping by repository, sorted by staleness within each— Repos are the unit of thought; most-neglected first serves the primary problem
  • Pure one-shot render on a non-TTY stdout, covered by goldens namespaced as tests/golden/fleet-dash-*.txt— Keeps the src/waybill.js:286 purity contract; the namespacing avoids colliding with status's existing fleet.txt and fleet-empty.txt
  • Io seam extended with TTY detection, clock and stdin injection points— Io is {out, err, signals} today with `out` a bare function (src/cli.js:24-29) — defining the seam in MVP stops the live phase from rewriting the verb's entrypoint
Full — target outcome ×5
  • Stacked-branch detection via git merge-base between open dockets in the same repository, rendered nested— The 'merge out of order' problem; needs no new state, which is what makes it acceptable in a stateless tool
  • tmux pane presence via a single `tmux list-panes -a -F` call matched on exact pane_current_path— The fleet join needs exact worktree paths, which the picker's name heuristic at src/picker.js:100 structurally cannot supply — this is a second, independent integration, not a replacement of it
  • Agent detection by descendant-process walk from pane_pid using one `ps` call; known agents named, other busiest descendants shown by command— pane_current_command reports `node` for Claude Code, which is why src/picker.js:70-75 already denylists it — the tree walk is the only honest answer
  • Live TTY mode: paint layer with frame diffing, ~2s refresh, progressive fill of slow data— The self-updating dashboard; isolated above the pure renderer so goldens stay valid
  • `q` to quit and `r` to force refresh via raw stdin, restoring cooked mode and cursor on every exit path including SIGINT— Minimal interaction; also lands the machinery that would make the deferred filter mode a small follow-up
Stretch — if time permits ×1
  • Progress indicator on stderr when a scan exceeds 0.5s, keeping stdout golden-clean
Out of scope — said no on purpose
  • Any change to `waybill status`, including its trunk-side fleet list — Explicitly excluded by the operator; guarded by asserting its suites and goldens are unchanged rather than by forbidding diffs to whole files
  • The existing fuzzy tmux name matching in src/picker.js and src/signals.js — Left exactly as-is; the fleet view adds its own exact-path join rather than unifying the two, and that duplication is a deliberate choice not an oversight
  • Persisted preferences or any configuration file — Cut during the interview; every session starts fresh, which also keeps the no-state-file property intact
  • Project on/off toggles and the interactive filter/tree mode — Cut once cwd-relative auto-detection removed the need to select projects by hand
  • A selection or cursor model, and acting on a selected docket — Interaction is capped at q and r; a cursor is what would turn this into a command center, and it is recorded as a future consideration instead
  • HTML output — Waybill prints strings; a generated artifact is stale the moment it is written
  • `--json` output from `fleet` — Follows the standing rejection at src/cli.js:305 — `next --json` is the machine-readable surface and a second one would be a second shape to keep in step
  • Any version bump in package.json or .claude-plugin/plugin.json — Release PRs own versioning in this repo; naming a version in a spec is a recorded past mistake (docs/ideation/learnings.md:32)
  • Windows support for the tmux and ps surfaces — tmux already implies a unix host; those columns degrade to blank elsewhere
Future — someday, maybe
  • The filter/toggle mode, reintroduced on top of the q/r raw-stdin machinery once it exists
  • Hybrid refresh — fs.watch on each .git plus a slow interval sweep — if the 2s poll proves too costly across many repositories
  • A selection cursor plus keys that act on the highlighted docket: attach its tmux window, advance a leg, retire a merged docket — the step that would make this a command center rather than a dashboard

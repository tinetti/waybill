Implementation Notes — Phase 3

Waybill Fleet · 2026-09-24 · tmux and agent signals

procs.js — what “busiest descendant” resolves to

Context
The spec asks for “the busiest non-shell descendant by command”, but the process shape it declares is {pid, ppid, comm, args} and the call it prescribes is ps -eo pid=,ppid=,comm=,args=. There is no busyness metric in that data, so “busiest” has no literal reading.
Decision
The shallowest non-shell descendant — the command the operator actually invoked. A npm test run reports npm rather than the node it spawned, which is both the more legible label and deterministic, so a golden file of the rendered fleet cannot flicker between two processes of the same tree.
Alternative
Add %cpu to the ps format and take the maximum. Rejected: it changes the declared Proc shape, macOS reports a cumulative average that says little about the last second, and the winner would then vary run to run — a dashboard column that changes while nothing changed is noise.

procs.js — positional parsing against a truncated comm

Context
The spec says to parse ps positionally with args taking the rest of the line. On macOS comm is the executable path, and a path can contain spaces — which would break a positional parse. Measured against this machine's real table: 1348 processes, 1158 of them with a comm truncated to exactly 16 characters, and zero lines that the greedy parse got wrong.
Decision
Keep the positional parse, taking comm as the first whitespace-delimited token. The truncation that loses a long path's basename is exactly why the spec also matches on argv[0], which arrives whole in args — so the two fields cover each other. args was additionally made optional, since a defunct process has none and dropping its line would break the parent chain between a pane and whatever is still running below it.
Alternative
Two ps calls with unambiguous single-field formats. Rejected: it doubles the cost of the one call the whole design is built around, to fix a mangling that only ever affects processes no pane is an ancestor of.

panes.js — a third export, paneFor

Context
The spec declares listPanes and panesByPath. The map that second one returns is keyed by resolved path, so a caller cannot look a docket up in it without performing the same realpathSync-and-strip-trailing-slash normalisation on its own side.
Decision
Export paneFor(byPath, dir) and keep the normalisation private to the module. One definition of “the same directory”, in the module that owns the join.
Alternative
Export the key function and let scan.js call byPath.get(key(dir)). Rejected: it publishes the representation instead of the operation, and a future caller that forgets the key function gets a silent miss rather than an error.

scan.js — the model key assertion had to move

Context
tests/fleet-dash-model.test.js:73 pins the exact key set of FleetModel. The spec's append-only tmuxAvailable / psAvailable flags break it, and the spec's Modified Files table does not list that suite.
Decision
Extend the assertion to the six keys and add a type-only check on the two flags. Their values depend on the machine the suite runs on — a developer inside tmux and a CI container disagree — so what the flags mean is pinned against stubs in the two new suites instead.
Alternative
Loosen the assertion to a subset check. Rejected: that assertion's job is to catch an accidental addition to the model, and a subset check cannot.

KNOWN_AGENTS — the spec's open item, closed against the real machine

Context
The spec left open whether its guessed agent list matches what the operator runs, and whether matching comm and argv[0] basenames is enough to find a real Claude Code session.
Decision
Kept the list as specced, after running the finished walk against this machine's live tmux server: 16 panes, 1340 processes, 94 ms for both calls, and eleven of twelve joined bays correctly named claude. The twelfth held a plain shell and correctly reported nothing — the false-positive case the whole design exists to avoid. claude appears with comm of claude, so the basename match is sufficient without reaching into argv[1].
Alternative
Also scan argv[1] for an agent entry point, covering a launcher that execs node <script>. Rejected for now: unnecessary against the observed shape, and every widening of the match is a step back toward the confident wrong claims the picker's denylist exists to suppress.

handover-runs-line · 2026-09-15 · Annotate the wrapper fence

Wrapper test — rewrote an assertion the spec did not name

Context
The spec's Modified Files row for tests/waybill.test.js named only the two negative tests. Scout found a third: the test at :411 renders a transfer leg with a bay — the wrapped case — and asserted output.includes('/spec:propose') === false. The annotation names that command, so the assertion inverted.
Decision
Rewrote it to assert what it meant: the leg command never appears as a fence (fences(output).flat()), which stays true and is the property the test was protecting.
Alternative
Deleting the assertion. Rejected — it guards against the raw command being fenced alongside the wrapper, which is a real regression the annotation does not make safe.

command-surface spec — amended a file outside the spec's File Changes

Context
The spec scoped the record update to openspec/specs/handover/spec.md. The reviewer found openspec/specs/command-surface/spec.md:87 and :109 carrying the same "ends in /waybill:next <branch>/<leg>" wording, which was literally true for empty-body handovers and is now false — those goldens end with the annotation.
Decision
Applied the same rewording ("the handover's last command is …"). Leaving it would reproduce the exact defect the change exists to remove: the repo's own record contradicting the tool.
Alternative
Recording it as follow-up work. Rejected — it is two sentences in a file already being read for this change, and the contract's out-of-scope list excluded prose whose claim stays true, which this one does not.

Annotation notation — the spec prescribed an unrenderable code span

Context
The spec wrote the annotation's shape with backslash-escaped backticks inside a single-backtick span. CommonMark does not honour escapes inside code spans, so it renders wrong in both the OpenSpec record and the spec itself.
Decision
Used a double-backtick span, which is the convention already in README.md:168, and fixed it in the ideation spec as well so the two do not disagree.
Alternative
Following the spec literally. Rejected — it was a notation slip in prose, not a decision about behaviour; the rendered output is unaffected either way.

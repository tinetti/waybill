## Conventions

- **Naming**: kebab-case files. Command files are `commands/<verb>.md` with an `# Waybill: <verb>` heading. Goldens are `tests/golden/<name>.txt` resolved by name. Test files are `tests/<module>.test.js`, one per `src/` module, all imported explicitly by `tests/index.js` (a new suite file must be added there).
- **Imports**: ESM (`"type": "module"`), relative paths with explicit `.js` extensions, node builtins prefixed `node:`. Node builtins first, then local, separated by a blank line. **Zero dependencies and no build step** — asserted at `tests/commands.test.js:269-278`.
- **Error handling**: three deliberate tiers, documented at `src/bay.js:14-23` — queries return `null` and never throw; loaders throw `file:line: message`; `BayError` carries operator-facing failures with a remedy after an em dash. Only `src/cli.js` writes to a stream or chooses an exit code. Error text uses backticked literals (`` `start` takes exactly one branch name ``) and is asserted by regex in the suites.
- **Types**: JSDoc typedefs only, no TypeScript. Every exported function carries a `@param`/`@returns` block, and the prose explains *why*, at length, not *what*.
- **Testing**: `node:test` + `node:assert/strict`, `describe`/`it`, `after(cleanupAll)` in every suite. Fixtures build real git repositories through `tests/helpers/repo-fixture.js`. Run with `npm test` (= `node --test tests/`, 33-36s) or scoped `node --test tests/<file>.test.js`. No linter or formatter is configured — `package.json` declares only a `test` script.
- **`${CLAUDE_PLUGIN_ROOT}`**: exactly that spelling in any `` !` `` line. A defensive `${CLAUDE_PLUGIN_ROOT:-}` is guaranteed to break (Claude Code rewrites the literal before bash sees it) and is swept for at `tests/commands.test.js:151-169`.

## Edge Cases for Phase 1

- **`DECLARED` must stay sorted.** `bay.md` sorts before `cleanup.md`, so it goes at index 0 — replacing `'start.md'` in place at `tests/commands.test.js:39` fails `assert.deepEqual` on ordering even though the sets match.
- **Rename with `git mv`**, not delete-plus-create: acceptance check `test ! -e commands/start.md && test -e commands/bay.md` (`contract.md:35`) passes either way, but history and review readability do not.
- **`UPDATE_GOLDEN=1` rewrites all nine goldens, not just `bay.txt`.** Three acceptance criteria (`contract.md:38-39`) demand `ideate/contract/specs/execute/cleanup/complete/refine/status/no-docket.txt` stay byte-unchanged. After regenerating, run `git diff --stat tests/golden/` and confirm `bay.txt` is the only file listed — and that its diff is the single line 7.
- **The booking edit and the assertion edit are one step.** Changing `bookings/waybill-bay.md:3` without `tests/inference.test.js:146` reds the inference suite; tasks.md §2.3 says explicitly not to stop on it, because the boundary guards `src/inference.js`, not its suite.
- **A "`start` is rejected as unknown" case does not exist yet.** `specs/command-surface/spec.md:38-40` requires it and tasks.md §2.2 names it as verification, but `tests/cli.test.js:323-328` only covers a `bogus` verb. This is a new test case, not a renamed one.
- **Usage-line padding.** The acceptance regex `^  (new|bay|next|status) ` (`contract.md:33`) needs a space immediately after the verb — `'  bay <branch>'` satisfies it — but the description column must be re-padded to keep `USAGE` aligned. That criterion still reads red after Phase 1 because it counts **four** verbs and `new` arrives in Phase 4; that is expected, not a regression.
- **Two more `start` literals in `src/cli.js` beyond the six §2.2 lists**: the import at `:10` and the call at `:173`, both `startBay`. They change only if the function itself is renamed.
- **`src/inference.js:113` is a trap, by design.** tasks.md §2.6 and `contract.md:84` both state the stale `/waybill:start` comment must be left alone; `git diff --quiet $(git merge-base main HEAD) -- src/inference.js` is the check on the whole approach. Verified clean today (merge-base `08d0c6f`, empty diff across all seven guarded modules).
- **Prose uses of the English verb "start" in `src/bay.js`** at `:192`, `:229`, `:239`, `:247` ("start the branch again", "start the bay") are not the command name and are outside §2.5's stated scope, which names only `:209`.

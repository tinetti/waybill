Implementation Notes — Phase 5

Stock review leg and /waybill:review. Decisions the spec did not settle, and the places the codebase had moved under it.

The three-state stamp contract — the detached-HEAD guard moved into the stamp

Context
The spec's Implementation Details printed the stamp one-liner without the guard, then added it separately in the Error Handling table: "if $b is empty or HEAD, exit 1 before probing". Two versions of one line, and the printed one is the one an implementer copies.
Decision
The shipped stamp carries the guard as its second statement: case "$b" in ''|HEAD) exit 1;; esac. Exit 1 rather than 125, as the error table specifies — a detached HEAD is a repository state, not a forge that could not answer, and warning about it here would double up on the detached-HEAD warning resolveLeg already emits. Covered by a test that checks out --detach with an open-reporting gh stub on PATH and asserts not-done: the assertion only means something because the stub would otherwise say yes.
Alternative
Shipping the printed one-liner verbatim and letting an empty $b reach gh pr list --head "", which lists every open request on the repository and would stamp the leg from somebody else's work.

Deterministic goldens — forgePath reached further than the spec listed

Context
The spec named tests/waybill.test.js and tests/inference.test.js as the two suites needing forgePath. Measured, six do: a real gh on the developer's PATH also reached tests/cli.test.js (golden comparisons, plus "raises no warnings of its own for a fleet that resolved cleanly", which failed outright on this machine), tests/bang-lines.test.js, tests/booking-swap.test.js and tests/bookings-overlay.test.js.
Decision
Every suite that resolves a leg against a real repository now builds its PATH with forgePath. The two whose fixture must reach cleanup — the booking swap and the overlay CLI case — pass 'open'; the rest take the default 'none'.
Alternative
Patching only the two suites the spec named, which passes on a machine with no gh and fails on one that has it — exactly the developer-dependent-goldens failure mode forgePath exists to close.

Fixtures — two inference tests now assert review, not cleanup

Context
Four tests asserted that a docket with every box ticked resolves to cleanup. Two of them are about the terminal leg; two — the archived-change and inherited-change cases under the change id is scoped to the branch — are about execute being stamped, and only name cleanup as "the next one along".
Decision
The two terminal-leg tests keep their subject and gain 'open'. The two execute tests keep their bare PATH and now assert review — which is the honest answer for that repository and keeps the test about the thing it was written for.
Alternative
Giving all four 'open'. That would have left two tests silently asserting a forge state they do not care about, and hidden the one behaviour change users will notice most: a finished docket now stops one leg earlier.

Prose sweep — three surfaces the spec's line list did not name

Context
The spec's Modified Files tables were written against line numbers that phases 3 and 4 had already moved, and its acceptance grep (of 7|7/7|7[- ]legs|seven[- ]legs?) cannot see a bare "leg 7" in prose. Re-grepping for leg 7 and row 7 found three more: src/fleet.js (twice, in the doc comment explaining what a docket in flight is), README.md's "the bay is cut at leg 2 and removed at leg 7", and README.md's "Leg 7 is the one most likely to be wrong for you anyway".
Decision
All three renumbered to 8. The install paragraph's list of slash commands was also stale before this phase — it omitted /waybill:cleanup and /waybill:doctor — and since the sentence was being edited to add /waybill:review anyway, all three were added rather than leaving a sentence that contradicts the tool in a line this phase touched.
Alternative
Editing only the enumerated lines. The acceptance grep would still have passed, and the documentation would still have told the reader the route has seven legs.

Open items — all three resolved, two of them by doing nothing

Context
The spec closed with three unresolved items: help.js's stampOf labelling the review row repo state; which state the ride-along's new section should show; and whether tests/legs.test.js pins the full leg id list.
Decision
The label stays repo state, as the spec recommends — a per-leg literal in help.js would be a second place stating a fact the booking owns. It is mildly wrong (review reads forge state) and is worth a generic stampCmd-aware label in a later pass. The ride-along shows the no-request state, because tests/golden/review.txt is that render and the fence is compared byte for byte; the prose around it is written as "the work is finished and nobody is on it yet". tests/legs.test.js needed no edit — phase 4 left it count-free and id-list-free, asserting only the anchor, the terminus, and that every leg is judged by something.
Alternative
Adding a forge state literal to help.js keyed on the leg id, which is the drift tests/commands.test.js's model/effort sweep exists to prevent.

Cost measured, not estimated — the suite is ~45 s slower

Context
The spec named the per-inference cost of the review stamp ("one subprocess on every waybill next") but gave no figure for the suite, which it put at ~173 s.
Decision
Recorded rather than optimised: node --test tests/ now runs in ~250 s for 605 tests. The increase is one /bin/sh per resolveLeg plus one stub directory per forgePath call. With gh and glab off PATH the stamp short-circuits on command -v and never touches the network, so none of it is I/O wait. Memoising the stub directory was rejected: cleanupAll runs per test file, and a module-level cache would hand a later file a path that had already been deleted.
Alternative
A module-level stub cache, which is faster and wrong in a single-process run.

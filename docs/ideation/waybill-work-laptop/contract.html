# Review: docs/ideation/waybill-work-laptop/spec-phase-1.md
The problem

01Waybill is usable on this laptop today only by accident and only in an old form. Claude Code exposes a plugin's `bin/` directory on PATH, so the `waybill` CLI here resolves to `~/.claude/plugins/cache/tinetti/waybill/0.3.1/bin/waybill` — the CLI is silently version-pinned to whatever plugin build is cached, five minor releases behind the 0.8.0 working tree. That is why this machine offers `/waybill:start` and not `/waybill:new` or `/waybill:bay`, and why `wyb` does not resolve at all: there is no `bin/wyb` file, only a `package.json` bin alias that requires a real `npm link`.

02Three documented setup steps were never performed here. `openspec` is not installed, so legs 5 and 6 fall back to parsing `tasks.md` silently (src/openspec.js:12,31-33). `~/.claude/commands/spec/` does not exist, so the bare `/spec:propose` and `/spec:apply` those legs emit cannot resolve (README.md:335-347). And `glab auth status` returns 401 against gitlab.com, while work runs on a self-hosted instance — so the forge CLI is present but points nowhere useful. None of these failures announce themselves.

03Nothing on this machine is hostile to waybill. glab, gh, jq, tmux and Node 26 are all present; the `ideation` plugin is installed; `/mar`, `/mr-review` and `/cpr` all exist. This is staleness and missed setup, not a corporate-environment problem.

04The deeper gap is that the route does not describe how work actually ships here. Waybill's stock route runs execute -> cleanup, but work is GitLab and Jira: commit, push, open an MR, get it reviewed, then merge. A route with a hole at the step you repeat most is a route you drift off.

05There is no way to discover any of this except by hand. Waybill ships no doctor, preflight, or setup command (src/cli.js:588-593); prerequisites exist only as README prose. Diagnosing this one machine took a dozen shell probes, and that cost recurs on every new machine.

Goals ×7
01 `waybill doctor` exists as both a CLI verb and a slash command, reports every prerequisite and setup gap with the exact remediation command for each, and exits 0 on this machine once setup is complete.
02 This laptop runs the current waybill release with every setup step done: plugin updated off 0.3.1, `wyb` resolving outside the plugin cache, `openspec` installed, `~/.claude/commands/spec/` populated, and `glab` authenticated against the self-hosted work host.
03 Waybill's route carries a stock eighth `review` leg whose done-signal is forge-detecting, so it stamps correctly on GitLab work repos and on waybill's own GitHub repo without either forge CLI being mandatory.
04 The review stamp distinguishes three states, never conflating them: no MR yet, MR open and unreviewed, and the forge CLI present but unusable (401, wrong host, missing binary).
05 The stock route is runnable on a machine with no user-supplied review skill — `/waybill:review` depends on nothing the plugin does not ship.
06 The leg count is derived from `LEGS` everywhere: no test literal, README sample, guide sentence or help card asserts a fixed total.
07 A machine-local overlay at `~/.waybill/bookings` binds review, bay and cleanup to this machine's GitLab and Jira carriers, leaving the personal machine's route untouched, and one real work ticket traverses all eight legs.

MVP — must ship ×2
  • Machine setup to a known-good baseline: plugin updated off 0.3.1, npm link for `wyb`, `openspec` installed, `~/.claude/commands/spec/` symlinked, and `glab` authenticated against the self-hosted work host— Everything else is verified on this machine, so the machine has to be trustworthy first — and it delivers a usable waybill here on day one, before any code changes land.

Full — target outcome ×8
  • Exit 127 from a stampCmd becomes a visible warning naming the missing binary instead of a silent 'leg not done'— Narrower than first contracted. `evaluateBooking` already warns on exit 127 via runStamp's notFound flag; the real gaps are that the exported `stampedByCmd` (src/bookings.js:267-270) discards the distinction and the warning never names the binary. Moved out of MVP because every stock booking is `stampCmd: false`, so nothing in the repo today can exit 127 — it only bites once the review leg stamps via a forge CLI.
  • `~` expansion in the WAYBILL_BAY_DIR and WAYBILL_BOOKINGS_DIR env tiers and in the `waybill.baydir` git tier— Widened after critique: only `waybill.bookingsdir` expands today, via configPath's --type=path at src/repo.js:31. `waybill.baydir` reads a plain `config --get` at src/repo.js:134, so the parity this fix claims does not currently exist anywhere.
  • De-hardcode the leg count: derive totals from LEGS, add a generic stampPath/stampCmd fallthrough in legIsDone, and add tests/legs.test.js asserting bay stays anchor and cleanup stays terminus— Smaller than first contracted: src/waybill.js:67-68,85 and src/help.js:80 already interpolate LEGS.length, so the renderer was never hardcoded — only test literals and prose were. What remains is a 25-site test sweep, one `index: 7`, and moving the bay/cleanup pairing out of legIsDone's two `leg.id ===` literals (src/inference.js:22-23) into a declarative map so phase 5 needs no inference.js edit at all. The `after:` splice mechanism was cut because nothing in scope declares a non-stock leg.
  • Stock eighth `review` leg with a forge-detecting done-signal that distinguishes no-MR, unreviewed-MR, and unusable-CLI— A glab-only stamp would stall waybill on its own GitHub repo. The three-state verdict exists because an unauthenticated glab exits non-zero rather than 127, so the exit-127 warning alone would not catch the 401 this machine currently returns.
  • `/waybill:review` wrapper — detect the forge, push, open the PR/MR, hand off for review— The one leg that must work on a bare machine is the one leg that cannot depend on a skill the user supplies separately. The work overlay still replaces it whole.
  • Cut and publish the release carrying the eight-leg route, then install it on this laptop and confirm it reports eight legs— Every /waybill:* command runs node "${CLAUDE_PLUGIN_ROOT}/src/cli.js" (commands/status.md:33), so the plugin cache is the runtime.   • Work bookings overlay at `~/.waybill/bookings` rebooking five legs: review pinned to glab + /mr-review, bay naming branches JIRA-123/short-name, cleanup routed to /mar, and — because work uses ideation rather than OpenSpec — specs to /ideation:ideation and execute to /ideation:execute-spec— Uses waybill's designed per-machine extension point, so the work route never leaks onto the personal machine.   • A `review` scenario fixture in tests/fixtures/, and sweeping every prose surface that claims seven legs — five known hits in README.md and docs/guide/, in word form not digits— tests/inference.test.js:74 ties fixture count to LEGS.length + 1, so the suite enforces the fixture itself; the prose surfaces do not enforce anything, which is exactly the next-from-anywhere learning in docs/ideation/learnings.md.
Stretch — if time permits ×2

Out of scope — said no on purpose
  • `after:` frontmatter splicing to add non-stock legs — Cut after critique. Once `review` ships stock, nothing in scope declares a non-stock leg — the work overlay only overrides review, bay and cleanup, all of which already exist. Building the extension point now means building it with no consumer, on the critical path, against a deliberate invariant.
  • `waybill doctor --fix` auto-remediation — Several remediations — plugin update, npm link, global git config, symlinks into ~/.claude — mutate state outside any repo. Doctor stays a diagnosis, and the human runs the fix.
  • Generalising the hardcoded `origin` remote (src/repo.js:202,306; src/bay.js:153) — Every remote in play on both machines is already named origin. Real latent defect, but nothing described here exercises it.
  • Committing a `.waybill/bookings` overlay into work repos — It would duplicate per repo, and personal tool configuration does not belong in a corporate repository.
  • A scripted live GitLab dry-run harness driving all eight legs against a scratch project — Needs a throwaway project, network and real MR creation; the fixture plus one live run buys most of the confidence for a fraction of the setup.
  • Doctor pre-flighting the binaries referenced by an overlay's stampCmds — The exit-127 fix already surfaces a missing binary at route time, which is when it matters.
Future — someday, maybe
  • `after:` frontmatter splicing, if and when an overlay genuinely needs a leg the stock route does not have
  • Configurable remote name, so a corporate mirror or an `upstream` remote works (src/repo.js:202,306)
  • Squash-merge detection in cleanup — `git branch --merged` misses squash merges, currently handled by prose only (commands/cleanup.md:52-64)

  • Bay exclusion via .git/info/exclude is per-clone and does not travel between machines (src/bay.js:88)
